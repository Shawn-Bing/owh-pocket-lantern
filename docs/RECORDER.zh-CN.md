# 整夜诊断记录工具 0.1.1

这是独立的 `owh-recorder.exe`。它记录掉线前后的证据，不发送按键、不点击、不重启游戏，也不结束游戏或 Neac 进程。可以和原来的 PowerShell Shift 脚本一起运行，不需要重新录制助手模板。

0.1.1 修复了 NVIDIA 常驻悬浮层导致的截图误判。无需关闭 NVIDIA 悬浮功能；普通窗口遮挡仍会跳过截图。截图失败时，界面和 `screens.jsonl` 会显示具体原因及遮挡程序。更新前先停止并关闭旧记录器，重新打开新版后点击开始记录，旧会话仍保留。

## 今晚怎么用

1. 打开 `owh-recorder.exe`，保留“每 30 秒保存游戏截图”，点击 **开始记录**。
2. 照常用你已验证的 Shift 脚本挂机。脚本依赖 CapsLock 时保持其开启。为了保留原始故障现场，今晚建议关闭助手的自动恢复，避免掉线后立即重新启动掩盖状态。
3. 切回游戏，让游戏窗口保持可见且无遮挡；可以缩小，但不要最小化。等约 30 秒，确认记录器的截图数增加，记录目录的 `screens` 中有正常游戏图片。看计数时记录器可能挡住游戏，检查后切回即可。
4. 记录器可以最小化，游戏不要最小化。不要关闭记录器窗口；关闭它会停止并保存。录制本身不会阻止系统睡眠，也不会修改电源设置。
5. 明早发现掉线，先点击 **标记此刻**，再点 **停止并保存**，等状态变为“记录已停止”。也可以双击同目录的 `stop-recording.cmd` 请求停止。
6. 点击 **打开记录目录**。保留整个会话文件夹，把它的完整路径告诉 Codex 即可在本机分析；不必先上传或公开分享。

记录目录默认在程序旁边：`recordings\年月日-时分秒-PID`。每次开始新建独立目录，旧记录不删除。记录器每次最长运行 18 小时、数据上限 512 MiB；剩余磁盘空间低于 256 MiB 时停止。停止原因写入 `summary.json`。上限之外只写少量收尾说明，不循环覆盖旧证据。

## 为什么采集这些

| 数据 | 频率与内容 | 能帮助判断什么 |
|---|---|---|
| 游戏截图 | 每 30 秒一张，JPEG，宽度最多 960；观察到进程变化、已连通过的探针连续 3 次失败或手动标记时，临时每 5 秒一张、持续 1 分钟 | 第一次出现错误的大致时段、具体错误文字、仍在房间还是返回登录；常规截图时间精度约 30 秒 |
| 进程与窗口 | 每 5 秒；Overwatch、OWNeacClient、NeacLoader、战网、战网 Agent、助手和记录器；PID、父 PID、创建时间、CPU 累计时间、内存、线程/句柄、窗口响应/前台/最小化状态 | 区分游戏退出/重启/无响应、Neac 是否仍在、助手是否退出，以及资源是否异常增长 |
| 网络参考探测 | 约每 5 秒对当前可用 IPv4 网关（最多 4 个）与 `223.5.5.5`、`119.29.29.29` 发小 ICMP 包，单次等待最多 600 ms | 对比局域网与公共参考连通性，观察持续故障、延迟突增、恢复时间；不探测游戏服务端，不发送账号或日志 |
| 网卡和连接表 | 网卡状态、累计收发字节/丢弃/错误，每 5 秒；网关与 DNS 配置每 30 秒检查；只保存上述进程的 TCP 对端/状态和 UDP 本地绑定，含 IPv4/IPv6 | 网卡掉线、路由变化、连接消失；网卡计数包含该网卡上其他程序流量 |
| 输入观察 | 左 Shift 高位状态约每 10 ms 采样，汇总到 5 秒样本；CapsLock 读取值、系统距最后一次输入的时间、采样间断 | 帮助判断点按是否停止，或依赖 CapsLock 的脚本是否可能被关闭；不是键盘文字记录，不区分物理/模拟按键，也不能证明游戏接收了输入 |
| 原生日志 | 每分钟保存新增部分；每个目录选最近 16 个 `.log`，每份每次最多 64 KiB；识别截断、文件替换，记录省略字节 | 对照战网/Neac/助手已有错误信息；包括启动前的少量日志尾部作为基线 |
| Windows 事件 | 每分钟；System 警告/错误及电源/时间变化，相关游戏应用崩溃/挂起/WER，WLAN 与 NetworkProfile 已有通道 | 网络重连、休眠/唤醒、显示驱动或应用错误；不启用额外审计通道，不读取 Security 日志 |

原生日志来源：系统“文档”目录下的 `Overwatch\Logs`、`%LOCALAPPDATA%\Battle.net\Logs`、助手的 `agent.log` 及轮转日志，以及守望先锋安装目录的 `log` / `logs`。安装目录优先读取助手中已配置的 OWNeac 路径，也可通过正在运行的游戏查询；缺失或拒绝访问会记录下来。

所有结构化记录同时保存 UTC 时间与系统单调运行毫秒数；会话另存本地 UTC 时差。这样能对齐截图、探测、采样与原始事件，也能发现时间跳变或采样中断。系统事件保留 Windows 原始 XML 中的事件时间；事件采集遇到长间隔时扩大回查窗口，正常每次重叠回查并去重。

## 不应过度解读的地方

- 公共地址 ping 正常，不代表游戏使用的线路或 UDP 连接正常；某个地址一直不回 ping，也不能当成当晚掉线的原因。最有价值的是之前稳定回复的目标在同一时段出现变化，以及多个独立来源相互印证。
- Windows UDP 表只有本地绑定，不能从这里得到游戏 UDP 对端、逐包丢包率或断连原因。本版不抓取网络包正文，不做游戏协议解密，不读取进程内存或崩溃转储。
- 游戏窗口被遮挡、最小化、超出可捕获屏幕范围或处于安全桌面时跳过截图，记录具体原因。画面不可见期间不会凭空标记为“正常”。不截整个桌面，也不主动切换焦点。
- 允许 NVIDIA 的被动悬浮 HUD（按进程名、窗口类和窗口样式共同识别），以及系统隐藏/全透明窗口。游戏区域内实际显示的 NVIDIA 性能数字或通知可能一起出现在截图中；不把任意鼠标穿透窗口都当成透明窗口。
- Shift 与 CapsLock 是采样/系统 API 观察值；短脉冲可能漏采，CapsLock 读取也可能受线程键盘状态影响。输入计数和系统空闲时间都不能证明游戏接受了动作。
- 原始日志可能为空、独占打开、加密或未及时刷新。失败代码、省略字节、扫描上限和来源缺失会记录，不把读不到解释为没有错误。
- 如果进程/网络数据都正常而游戏仍报断线，原因仍可能在服务端、具体游戏网络路径、会话认证或房间规则，需要结合错误文字与原生日志继续缩小范围，不能仅凭这份采集断言。

本机短测发现 `文档\Overwatch\Logs` 内的游戏日志为空且被独占打开（Windows 错误 32）。记录器记录了这一限制，并成功保留了其他来源；没有尝试绕过文件锁或安全组件。

截图可能包含昵称/聊天，原生日志可能包含账号、认证相关信息、路径和 IP。它们只保存在指定本机目录，记录器不会上传。分享前应由你确认内容；在本机分析不需要上传。

## 文件说明

| 文件 | 内容 |
|---|---|
| `session.json` | 版本、开始时间、采集选项、时长/容量上限、本地时差 |
| `summary.json` | 停止时间、原因、样本/截图/缺失数、字节量；强制结束进程或断电可能来不及生成 |
| `timeline.jsonl` | 开始/停止、进程变化、探针异常候选、恢复、用户标记、路由、采集错误 |
| `samples.jsonl` | 每 5 秒的进程、窗口、输入观察、网卡、连接表与系统资源 |
| `probes.jsonl` | 每次 ICMP 参考探测的开始时间、返回状态、耗时与 RTT |
| `screens.jsonl` / `screens\*.jpg` | 截图与时间映射，或跳过的原因；文件名为采集时的系统运行毫秒数 |
| `windows-events.jsonl` | 筛选的 Windows 事件原文和读取时间 |
| `sources.jsonl` / `sources\*.log` | 来源路径与保存片段对应关系、原始字节偏移、身份变化与省略量；原始编码保留 |

JSONL 每行独立，写入即刷新；意外退出后已完成的行仍可分析。CPU 字段为累计时间，分析时需用相邻样本差值计算占用。网卡计数同理，发生重置时不能直接作正常增量。

## 开发与验证

使用 `scripts/build-windows.ps1` 构建，或单独执行：

```powershell
cmake --build build/windows --target owh-recorder recorder-tests
ctest --test-dir build/windows -R recorder --output-on-failure
```

可用隔离目录做有界无界面测试：

```powershell
.\owh-recorder.exe --headless --seconds 35 --output E:\test-recording
# 不截图、不读取原日志、不发送主动探针
.\owh-recorder.exe --headless --seconds 5 --no-screenshots --no-source-logs --no-probes --output E:\test-recording
```

`--headless` 使用独立停止事件，只按指定时长停止，不受正常窗口的 `stop-recording.cmd` 影响。测试不会使用桌面按键或启动/结束游戏。

2026-09-20 已完成：

- 0.1.0 实际桌面 35 秒只读采集：7 个进程/网络样本、29 个参考探测、25 个日志片段索引、1 条 Windows 事件；JSONL 全部可解析，正常按时停止。当时 2 次截图被判为遮挡；后续诊断确认常驻 NVIDIA 悬浮层会造成该误判。

遮挡判断参考：[DWM 窗口隐藏状态](https://learn.microsoft.com/en-us/windows/win32/api/dwmapi/ne-dwmapi-dwmwindowattribute)、[分层窗口透明度](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setlayeredwindowattributes)。NVIDIA HUD 的兼容规则来自本机诊断，不将鼠标穿透样式等同于视觉透明。

API 依据：[Windows 事件查询](https://learn.microsoft.com/en-us/windows/win32/wes/querying-for-events)、[TCP 表](https://learn.microsoft.com/en-us/windows/win32/api/iphlpapi/nf-iphlpapi-getextendedtcptable)、[UDP 表](https://learn.microsoft.com/en-us/windows/win32/api/iphlpapi/nf-iphlpapi-getextendedudptable)、[ICMP 探测](https://learn.microsoft.com/en-us/windows/win32/api/icmpapi/nf-icmpapi-icmpsendecho)。游戏本身的网络提示亦可作为截图证据，参见 [暴雪网络诊断说明](https://us.support.blizzard.com/article/000037007)。
