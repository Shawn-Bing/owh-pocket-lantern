# Windows 开发版 0.5.13 试用指南

日常使用简易版见 [简易版说明](SIMPLE_EDITION.zh-CN.md)，只需 EXE，识别资源内嵌。下方是保留高级功能的开发版操作。

0.5.12 新增“前台使用（实验）”，采用旧样本的定向窗口消息。局内确认后可最小化，暂停 OCR/导航/恢复；详见 [前台使用说明](BACKGROUND_USE.zh-CN.md)。以下常规前台流程继续适用。

0.5.11 自定游戏采用双击目标模式 → 识别人数 → 双击有空位大厅。满人、人数模糊或行位置无法确认时等待；五次失败后暂停十五秒再试。保留配置，关闭旧助手后打开新版，并确保 `ocr-worker.ps1` 与 EXE 同目录。

0.5.10 游戏网络断线后返回登录或连接错误页面，连续确认并短暂等待约 3 秒即关闭游戏、核验残留并通过战网重启。自动恢复不再限制每小时次数；启动超时也持续重试，保留 30/60/120 秒冷却，后续最多间隔 120 秒。界面的恢复次数仅是累计统计。原有“人工操作待机”仍生效：你持续使用其他窗口时暂停，停手后继续；需要挂机自动重启时启用“自动恢复”。战网账号登录、验证码和 NeacProtect/UAC 授权仍需手动处理。

0.5.9 若 NeacLoader 当前日志显示启动被取消（1223），会立即显示具体原因，不继续两分钟空等或自动重试。NeacProtect / UAC 授权仍需手动确认；处理后点“重启游戏”，或自行启动游戏，助手发现游戏后会继续监控。游戏终止请求已被接受但退出较慢时，会继续等待并核验，期间不再次启动；终止被拒绝时显示具体错误。

0.5.8 修复死斗结束后返回街机页面时，重复点击已打开的街机入口并暂停。会保留整图详细识别的卡片文字，补充局部原色 OCR，确认死斗卡片后继续匹配；暂未读到卡片时等待重识别。先关闭旧助手，再解压运行新版，配置保留。

0.5.7 重上游戏会核验并清理 NeacLoader.exe 与 OWNeacClient.exe。仍只填写 OWNeacClient.exe 完整路径，加载器从同一目录确定，无需改配置。清理失败会显示具体原因并停止启动；启动后 120 秒无游戏进程时，允许在恢复预算内清理后重试一次。NeacProtect 管理员授权仍由你确认。

0.5.6 可拖动窗口边框和四角调整大小，也可最大化；配置区高度不足时使用滚轮或右侧滚动条。开始、停止和底部状态操作始终可见，Tab 会把当前设置项滚动到可见位置；配置和运行逻辑不变。

0.5.5 兼容选英雄按钮“选择 / 继续”，小字漏读时由两排英雄头像边框与实时按钮联合确认。赞赏结束后识别“感谢赞赏！”并按 Esc；第二次成功赞赏也安排独立退出步骤，随后继续排队。先关闭旧助手，再运行新版，配置保留。

0.5.4 补齐进房后的英雄确认、死斗随机键后的鼠标左右键，以及结算后按 N → 赞赏未赞赏名片 → 关闭 → 再次排队。默认确认当前高亮英雄；赞赏使用游戏默认 N 键。配置可保留，先关闭旧助手，再打开新版。

0.5.4 修复 1080p 桌面下小窗口街机入口的小字 OCR 漏识别，并区分旧导航被当前模式排除与真正的模板失配；无需恢复 2K，也无需清空配置。

0.5.4：选择“自由死斗 / 自动匹配”，开启“发送挂机按键”、确认演练设置，点普通“开始”。自动路线是街机先锋 → 死斗 → 选择英雄 → 确认选择。已经在死斗局内时，可点“已在局内，开始挂机”；仍需连续确认 HUD，停止手动操作后接管。已有战网会恢复原窗口，不需退出重开，也不用删除旧配置。

0.5.0 主程序已内嵌管理员权限清单：双击 `overwatch-helper.exe`，按 Windows UAC 提示授权即可，无需另外右键选择“以管理员身份运行”。

适用：Windows 10/11 x64，国服战网版。先把 ZIP 全部解压到一个普通目录，再运行 EXE。

仓库本机构建完成后，也可以直接从 `dist` 目录运行。首次建议先点“运行诊断”确认进程、启动器和模板情况；报告保存到配置目录的 `diagnostics.txt`。也可双击 `diagnose.cmd`，它会生成并打开正式配置的诊断报告，不启动游戏或发送输入。

## 先演练当前页面

1. 关闭旧助手，打开新版 `overwatch-helper.exe`，确认标题为 0.5.11。保留“演练”“本地 OCR / 自动校准”和“自动恢复”；“国服旧截图预设回退”可保留。`ocr-worker.ps1` 必须与 EXE 在同一个目录。
2. 核对战网和 OWNeac 路径，例如本机的 `D:\Battle.net\Battle.net.exe`、`D:\Overwatch\_retail_\OWNeacClient.exe`；其他电脑填写自己的安装位置。战网保持已保存的登录会话。
3. 选择“模式”。自定义房间填写目标名，默认“最稳轮换版”；自由死斗无需填写房间。点“开始”，让目标窗口处于前台且无遮挡，核对状态中的页面与拟执行动作。
4. 按 F8 停止，取消“演练”，再点“开始”。“发送挂机按键”控制局内 Shift / 随机键；取消它仍可进行导航与匹配。继续使用外部 PowerShell 挂机脚本时取消该选项，外部脚本的停止方式仍由它自己决定。
5. 需要从战网重启时先在演练模式点“重启游戏”，确认恢复配置；停止并取消演练后，再点该按钮实际执行。NeacProtect / UAC、密码、验证码和过期认证由你手动处理。**F8 停止助手并释放它持有的全部按键。**

OCR 使用 Windows 内置简体中文语言功能，首次识别可能需要数秒。普通识别最高放大 2 倍，未确认页面或停在浏览页时补充最高 3 倍的详细识别，保留并合并原结果，帮助读取 998×576 等小窗口中的房间完整标题。补充识别没有有效结果时保留有效的普通浏览页识别；发现多个不同模式时仍等待更精确目标。若提示简体中文 OCR 不可用，请安装 Windows 对应语言功能并重启助手，或使用已有预设和下方手动校准。日常 OCR 无需模型。可选演示学习连接你已经运行的本机视觉模型，附带的录制/标注工具无需安装 Python。

界面改版后不必先重录所有页面：助手先检查已有多处锚点，失效时重新读取页面文字和实际按钮位置，连续确认后写入 `%LOCALAPPDATA%\OverwatchHelper\adaptive-profile.json`。缓存按工作模式、目标名及窗口布局区分，更新不会降低旧图匹配阈值。新结构或文字无法识别时仍需校准；这不保证所有未来版本自动适配。

不用每次都点“重启游戏”：在大厅时点“开始”继续导航；已经手动进入目标房间时点“已在局内，开始挂机”，为这次运行声明当前游戏就是目标房间，随后仍连续确认局内 HUD。已保存会话下，可识别可用的登录、重新连接和进入游戏按钮；不会自动填写或保存游戏账号密码。更新、下载、灰色不可用按钮和已在游戏的状态会等待。

## 自定义房间 / 战令

自动路线为“开始 → 更多模式 → 自定游戏 → 目标卡片 → 自动加入”。目标按完整标题分组，精确全文匹配优先；两张同为“托比昂战令 最稳轮换版”的卡片属于同模式的多个可选房间实例。若多个不同完整标题都含“最稳轮换版”，请把“房间”填写为所需模式的完整标题；不能区分模式或目标不存在时会等待。读不到斜体页头时，仍需同时确认筛选/搜索栏与顶部模式列表标签，不靠单个搜索字样判断页面。按钮按当前 OCR 位置点击，非默认目标不会使用旧预设中的卡片坐标。

确认目标卡片并选择后，对可用的加入按钮每 **200 ms** 点击一次，单轮最多 **5 秒 / 25 次**，每次仍检查画面。本轮未进入房间时，下一轮选择下个相同完整标题的实例；5 轮无进展后等待 **15 秒**，然后重新选择并尝试。进入未知/加载画面立即停止连点。成功发送目标加入后的候选保留 **180 秒**，覆盖本次约 69 秒的 Workshop 地图加载；随后必须连续两次确认房间大厅，或确认具有进房来源的局内 HUD，才算加入成功。地图介绍和黑屏均不确认进房，单次点击成功返回值也不证明进房。

浏览页每次重新识别，不学习或复用 Browser 缓存，避免选卡前后相同的页头遮住新出现的加入状态；已保存的 Browser 项自动忽略。Join 缓存核对完整标题、位置、页面和按钮，以支持快速连点；背景光效或无关人数变化无需重录，标题改变或卡片移动仍重新识别。旧版 Join 缓存自动重学，其他可用页面缓存可继续使用，无需手动删除缓存文件。

窗口化的视频设置页会根据顶部设置标签与默认设置上下文识别，按 Esc 返回后继续导航。改变窗口大小后仍须保持前台、无遮挡；新尺寸不适用的缓存会重新识别。

自定义房间已确认后，勾选“发送挂机按键”时按设置每秒点按左 Shift（20 ms）或前台持续按住。观战、加载和结算可保留同一房间会话；已识别菜单、错误、歧义、进程变化或停止会清除会话。`ACTIVE` 不证明本人已参赛或获得经验。

## 演示一次，让本地模型生成配置

1. 按 F8 停止助手，点击 **“演示 / 本地模型校准”**。默认模型地址为 `http://127.0.0.1:8080`；模型名称留空时自动发现唯一模型，多模型服务填实际名称。本机已有的 Qwen3-VL-8B 服务可直接连接，无需重新安装。
2. 点击“录制操作/页面”，在新窗口开始录制，再回到游戏实操。每页显示稳定后再点击；录制器保存实际点击前的画面及位置。F9 只采集当前页供自检；已在目标房间时按 F10 标记，停留约 1–2 秒收集第二帧验证，再按 F8 完成。
3. 返回学习窗口，点击“开始模型标注”。模型核对页面和点击，程序从真实截图采样模板并回放；Ready 房间规则缺少第二帧或跨帧失败时，只保留审查结果。仅 F9 的观察步骤不会直接生成动作规则。
4. 点击“查看结果”打开图文审查，检查截图上的锚点框、实际点击圈和验证状态。显示验证完成后点“导入配置”，或从主窗口“导入页面配置”选择已有 `profile.json`。导入会备份原 `cn-profile.json`，并同步该配置的房间目标。
5. 关闭学习窗口，回到主窗口先演练；确认页面后停止、取消演练并开始。学习窗口打开期间不能同时运行自动挂机或手动覆盖层校准。

F8 可取消这次录制或标注；取消标注只结束本软件拥有的标注进程，已运行的本地模型服务继续保留。详细文件位置、模型要求、更新后自检与失败处理见 [本地视觉模型指南](LOCAL-VISION.zh-CN.md)。

## 自由死斗 / 自动匹配

选择“自由死斗 / 自动匹配”，先演练再开启实际动作。助手识别死斗入口和开始按钮，等待匹配、处理英雄选择/重生，在连续两帧确认局内 HUD 后发送随机输入。

- 随机键为 **W、S、A、D、V、E、Q、左 Shift**，每次按住 **100–500 ms**，之间随机等待；沿用旧样本的键表与按住时长。
- “每秒点按 / 持续按住”选项仅用于自定义房间；死斗不长按 Shift。
- 未知页面、队列、英雄选择、菜单和结算会停止随机键。局内证据过期也会停下，不因已排过队就无限发送。
- 结算后优先使用重新匹配按钮；没有该按钮时，在确认本局结束后打开退出流程、确认离开，再从菜单进入下一次匹配。正常排队不会点击取消，局中不主动离开。

若已经在死斗局内启动助手，但该 HUD 无法自动确认，可按下方校准方法录制“死斗局内 / 随机按键”。仅圈选能区分死斗对局的稳定 UI；通用血条不够。完整真实死斗连续重排尚未实机验证，首轮请观察英雄选择、结算和下一次队列是否正确。

战网在网络恢复后自行弹出并遮挡游戏时，助手在 5 秒后尝试一次切回游戏；Windows 若拒绝前台切换，仍需手动切回。其他应用遮挡或最小化时无法检测游戏画面。

## 手动校准最小流程（自动识别不适用时）

如果你当前已经进入目标自定义房间，第一轮只需要录制一个“到达目标房间”页面：

1. 手动进入指定房间，把游戏设为窗口化；保持窗口完整可见。
2. 打开 `overwatch-helper.exe`。暂时保留“演练（不执行动作）”。
3. 校准对象选“游戏”，操作选“到达目标房间 / 持续 Shift”，页面名称填你容易辨认的名称。
4. 点击“3 秒后录制”。助手会切到游戏；三秒后截图覆盖在窗口上。
5. 拖动圈选一块**独特且静止**的房间标识/UI 特征。选取带有文字、图标或边缘的区域，避免纯色、英雄动画、计时器、聊天和会变化的数值。对局通用血条本身不能证明是目标房间。
6. 回到助手点击“开始”。游戏置于前台后，连续两次匹配应显示演练确认信息。
7. 按 F8 停止，取消演练，勾选“发送挂机按键”，方式选“每秒点按（20ms）”，再次开始。游戏失焦会停止发送。

状态显示 `ACTIVE` 表示本轮游戏已连续确认过房间参考，后续 HUD 短暂消失仍保留会话；不代表当前有效对局或已获得经验。**软件只能验证所选特征；是否能区分其他房间取决于校准区域。**

自定义模式默认使用你提供的脚本同类 `keybd_event` 点按，每次按下左 Shift 20 ms，约每秒一次，不需要 CapsLock。当前版本只在目标窗口位于前台时发送；失焦、停止或退出会释放自有按键。关闭助手会退出程序，不能关掉窗口后仍期待它工作。

## 手动配置完整恢复（关闭 OCR 和旧预设时）

1. 关闭旧助手，打开新版；正式配置仍使用原来的目录，导航录制保留。
2. 在已进入的目标房间，新增“到达目标房间 / 持续 Shift”，圈选 **E 技能的齿轮图标本体**，尽量避开周围场景、按键文字和数字。只录此参考不能区分其他托比昂房间，因此首次应由你确认已经进对房。
3. 演练确认后 F8，取消演练，选择每秒点按并开始。观察技能效果；切走窗口应停键、切回后恢复，再等到结算/下一局确认会话保留。若初始参考无法确认，可录另一份同类 E 图标样本；无需删除其他有效导航。
4. 在“OWNeac 路径”填写实际安装目录内的 `OWNeacClient.exe` 完整路径。只有游戏已退出、进程身份核验成功时才清理同目录 NeacLoader.exe 与该客户端；先结束加载器，再结束客户端。核验或结束拒绝时记录原因并重试最多 15 秒，到期停止启动，不把残留误报为清理通过。
5. 为蓝色掉线页录制“登录/错误页重启游戏”，圈选“抱歉，我们无法让您登录 / 连接战网服务超时”等稳定错误文字，**不要只圈纯蓝背景**。连续确认并短暂等待约 3 秒后恢复；识别到其他页面会清零。短时间待机/无采样采用现有掉线计时容忍，不把缺帧当成新的错误证据。不要把战网需要账号密码的登录表单录成游戏错误。
6. 把战网“进入游戏”以及“开始 → 更多模式 → 自定游戏 → 目标模式 → 自动加入”各页面录好。掉线后流程为：退出游戏 → 等待退出完成 → 清理核验过的残留 → 战网进入游戏 → 你处理 NeacProtect 授权 → 自动按录制路径重新进房。

冷启动/主动重启缺失先等待 3 秒；运行中游戏自行消失先等待 30 秒，避免把自行重启中的客户端当成残留。每次启动游戏后的 120 秒等待不包含检测到的安全桌面时间。

若需要画面检测持续工作，请让游戏处于前台且无遮挡；最小化或失焦时不能持续识别蓝色画面，也不会向其他应用点按。多录一份房间参考只增加小图模板采样；有效场次统计尚未实现。

## 自定义其他房间的导航

按你平时手动操作的顺序，为各个不同页面分别录制。例如：

| 当前页面 | 操作 | 第二次点击的位置 |
|---|---|---|
| 战网的守望先锋页面 | 战网启动游戏 | 启动按钮 |
| 游戏大厅 | 点击按钮 | 自定义游戏入口 |
| 自定义列表页 | 点击按钮 | 搜索入口或目标房间行 |
| 房间搜索页 | 输入文字并 Enter | 搜索输入框 |
| 搜索结果页 | 点击按钮 | 指定房间条目 |
| 房间详情页 | 点击按钮 | 加入按钮 |
| 目标房间 / 对局 | 到达目标房间 / 持续 Shift | 不需要 |
| 游戏内断线或登录页面 | 登录/错误页超时恢复 | 不需要 |

这只是流程示意，界面层级应按你的国服客户端实际页面录制。列表排序会变化时，不要把固定行号当成房间身份。优先使用搜索筛选，确保结果唯一后再标记加入位置。

“输入文字并 Enter”会点击校准的输入框、选择其中已有文字、写入设定内容，再按 Enter。不要把房间密码或账号密码当作普通搜索内容录入；配置文件以本机明文保存。

校准包含两个阶段：先拖动圈选页面特征；需要点击或输入时，再单击操作位置。**框出的特征区域与按钮位置可以不同。** Esc 取消覆盖层；F8 可取消录制倒计时或覆盖层。校准过程中不能启动任务。

多个“到达目标房间”样本、或多个“登录/错误页超时恢复”样本可以共存。同一类观察不会互相构成歧义；导航样本冲突、或房间与错误页冲突时会显示 `AMBIGUOUS` 并停止房间输入。应删除相似校准，选择更独特的页面区域，而不是降低阈值强行执行。一个页面需要多次同类操作时，应优先找出每次操作后可区分的视觉状态。

## 战网启动配置

程序尝试从常见安装位置发现 Battle.net。若路径为空或不正确，用“浏览”选择你平时启动国服战网的 EXE 或快捷方式。启动参数可以留空；不会自动添加未经验证的启动参数。

战网仅在后台托盘运行、没有可见主窗口时，助手会打开一次配置的战网程序以请求显示主窗口；仍未出现会等待并超时暂停。可手动打开战网后继续。

战网应保留有效登录状态，并显示正确的游戏页面。账号过期或验证码需人工处理；客户端更新期间助手等待按钮可用。每次开始或恢复时助手会请求前台切换，并在有限时间内重试核对；Windows 若拒绝请求，助手会停在 `WAITING_FOCUS`，你需要切到对应窗口。开启自动恢复后，战网持续遮挡游戏还会触发上文的一次切回尝试。

恢复规则：游戏进程缺失可启动配置的程序；窗口连续无响应 30 秒，或游戏登录/错误页经连续确认并短暂等待约 3 秒时尝试恢复。游戏内的登录表单关闭重启；战网账号表单不自动填入凭据。先请求正常关闭，再仅对身份已核对的游戏进程尝试结束并等待退出。残留核验失败时记录原因并限时重试，无法安全清理时暂停。恢复次数不限，间隔依次 30/60/120 秒，后续保持 120 秒。

启动后 120 秒未出现游戏会继续恢复并重试，不会因尝试次数用完而停下。授权取消/拒绝、配置缺失、普通导航操作没有前进等需人工处理，显示具体状态；NeacProtect/UAC 确认仍由你完成。自定义房间加入使用上文的连点/等待规则。界面恢复计数仅用于统计。

## 不开游戏也能验证

双击 `start-demo.cmd`。它会启动演示窗口和使用独立配置的助手。

先手动依次打开并校准：

1. 大厅标题区域 → 点击“进入自定义游戏”。
2. 房间列表标题区域 → 点击“加入测试房”。
3. 目标房间标题区域 → “到达目标房间 / 持续 Shift”。
4. 点击演示窗口“模拟断线”后，圈选断线标题 → “登录/错误页超时恢复”。

回到演示大厅（按 Esc），先演练再执行。正常流程是进入房间，并在前台演示窗口看到“左 Shift 点按”次数每秒增加。20 ms 脉冲很短，不需要一直显示按下。演示模式的断线持续确认时间是 5 秒，正式模式是 90 秒。F9 关闭演示窗口，可验证进程缺失后的启动与再次导航。

演示只验证软件流程，不证明国服游戏会接受所有模拟输入。

## 看板先在本机试

1. 在解压目录双击 `start-dashboard.cmd`，保持服务端窗口打开。
2. 打开浏览器访问 `http://127.0.0.1:8765`。
3. 服务端首次运行会创建 `owh-server-data`。用文本编辑器查看其中 `view-token.txt`，填到网页登录框。
4. 在 Windows 助手中填写看板地址 `http://127.0.0.1:8765`，把 `agent-token.txt` 填入“Agent 令牌”，再保存。
5. 数秒内应出现设备。停止挂机任务时仍会发送心跳；退出助手后约 90 秒看板标记离线。

两个令牌用途不同，填反会出现 HTTP 401。机器名需要在各台设备之间保持唯一。

## 部署远程看板

Windows 服务端可运行：

```powershell
.\owh-dashboard.exe -listen 0.0.0.0:8765 -data .\owh-server-data
```

Linux x64 包可运行：

```sh
chmod +x owh-dashboard-linux-amd64
./owh-dashboard-linux-amd64 -listen 127.0.0.1:8765 -data ./owh-server-data
```

公网访问应在前方配置 HTTPS 反向代理，再把 HTTPS 地址填入助手。HTTP 模式适合本机或受信任网络测试，因为令牌会随每次请求传送。反向代理需允许 SSE 长连接并关闭该路径的代理缓冲。服务端默认只监听回环地址。

本版用一个 JSON 快照持久化设备和最近 200 条事件，每 10 秒落盘；没有引入 SQLite 依赖。最多接入 128 台设备和 32 个并发查看连接，适合先行验证。

## 排障与反馈

- `WAITING_DESKTOP`：等待返回普通桌面；NeacProtect 授权需要手动处理，启动超时会暂停。
- `WAITING_FOCUS`：把目标窗口放到前台；不要最小化。
- `UNKNOWN`：OCR 或模板无法确认当前页。等待加载；持续出现时检查 OCR 错误、窗口大小与实际文字，必要时重新校准。未识别截图在配置目录的 `unmatched`。
- `AMBIGUOUS`：两份模板相似，重新选取独特特征。
- `INPUT_BLOCKED`：输入失败或目标焦点变化。助手与游戏的权限等级不同也可能造成此问题，需要结合实际提示排查。
- `BACKOFF`：恢复次数或间隔达到限制，界面会显示等待时间。
- 房间暂时不可加入：连点达到本轮上限，等待 15 秒后会继续尝试；未知画面不会被当成已加入。
- 死斗只导航、不发随机键：核对模式及“发送挂机按键”，确认已识别局内 HUD；排队、菜单、结算或证据过期时停键属于正常行为。
- 看板失败：确认服务端在线、地址可访问以及令牌用途正确；看板故障不会停止本地任务。

“配置与日志”会打开 `%LOCALAPPDATA%\OverwatchHelper`。日志 `agent.log` 超过约 512 KiB 后轮转一份。反馈时提供状态、相关日志以及实际页面截图；分享 `settings.ini` 前请移除 `token` 字段。

最新 0.4.1 日志和截图已出现自动加入后的 Workshop 局内画面；0.5.0 修复长加载及房内识别，并完成对应截图正反回放。**补丁后的完整挂机、稳定模型校准和死斗连续重排仍需实机确认**，本轮构建、测试及真实模型结果见 [验证记录](VALIDATION.md)。OCR 和模型图像只在本机处理，不上传看板。
