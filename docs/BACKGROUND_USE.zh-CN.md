# 前台使用 / 后台挂机（0.5.13 实验功能）

1. 将守望先锋设为窗口化，进入战令房间或自由死斗；选择对应模式并开始助手。也可用“已在局内，开始挂机”。
2. 进入当前选择的房间或死斗对局后，点击“前台使用”。0.5.13 已取消 OCR 前置条件；助手未运行时会按所选模式启动，再直接核验当前游戏进程、窗口与权限。简易版也有同名按钮。
3. 游戏自动最小化，你可使用其他前台软件。战令每秒定向点按左 Shift 20ms；死斗发送 W/S/A/D/V/E/Q/左 Shift 随机键 100–500ms，并跟一次 20ms 左/右鼠标消息。后台忽略“持续按住”选项，始终成对点按。
4. 切回游戏，或点“结束前台使用”，恢复 OCR 并重新确认当前页面。F8、停止和关闭助手都会取消后续发送并向原窗口释放本程序持有的键。

“演练（无动作）”开启时不发送任何按键；关闭“发送挂机按键”时只暂停识别。前台使用状态不写入配置，每次运行须主动开启。

## 沿用旧软件的实际路径

静态逆向 `reverse-analysis/analysis/ow/evidence/disassembly.asm`：`0x140001774–0x1400017EE` 先 MapVirtualKeyW，再向目标游戏窗口发送 WM_SETFOCUS，然后 PostMessageW(WM_KEYDOWN)，等待指定时长后 PostMessageW(WM_KEYUP)。松开消息携带扫描码与 0xC0000001。鼠标分支 `0x1400014E0–0x1400015A5` 同样是窗口定向消息、20ms 按下/松开。样本菜单注明“后台版：需要开窗口化，可最小化玩电脑”。

新版复用这个消息顺序，WM_SETFOCUS 改为有 150ms 超时的 SendMessageTimeoutW，防止目标无响应卡住助手。核验窗口所属 PID、进程创建时间与 EXE 名；停止和旧运行代次不能继续发送。后台路径不调用 SendInput/keybd_event/mouse_event，不移动系统鼠标，也不请求前台焦点；启用期间同时关闭所有全局输入入口。游戏重新获得前台时会中止后台按键并重新检测。

## 使用边界与验证

此模式暂停截图、OCR、页面导航、死斗结算重排与掉线恢复，避免使用电脑时抢焦点。最小化期间无法判断对局结束、被踢或断线；进程/窗口消失则停止后台模式并要求重新确认，不自动关闭或拉起游戏。死斗结算后请切回游戏让助手识别和重排，再重新开启前台使用。

界面显示 BACKGROUND_UNVERIFIED，表示 Windows 已接受定向消息或正在等待下次发送，**不表示守望先锋已响应**。当前客户端是否忽略最小化后的窗口消息，必须以技能触发、角色动作和连续回合结果实测；旧程序的实现不等于新版游戏一定兼容。若无效，切回游戏使用前台模式。

自动测试使用本程序创建的独立隐藏窗口，覆盖消息顺序与扫描码、左右键配对、停止释放、代次取消、进程身份变化、窗口销毁、无 OS 焦点切换、关闭全局输入及界面布局。没有向真实游戏发送测试输入。

Microsoft 说明：窗口消息与 Raw Input 是不同输入通路，PostMessage 成功不能证明游戏处理了输入：[Raw Input Overview](https://learn.microsoft.com/en-us/windows/win32/inputdev/about-raw-input)、[PostMessageW](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-postmessagew)。
