## 2026-10-09 · 0.5.10 登录页恢复与不限次数重试

本轮用户要求游戏网络波动后回到登录页时关闭并重新启动，以及长时间挂机不受恢复次数上限限制。最新日志在记录的 01:30:08～01:30:09 识别登录/连接错误，随后 01:30:14 起因人工输入进入待机。旧代码另有两个停止条件：错误页等待 90 秒、每滚动小时最多三次恢复；游戏账号表单也被统一归为 Ignore，与战网账号验证共用人工处理逻辑。游戏启动 120 秒无进程后还只自动重试一次。

现在游戏密码+登录，或账号+登录表单归为 LoginError / Restart；孤立密码文字不单独触发。已保存的游戏 Login / Ignore 校准在运行时规范化为恢复，配置和旧缓存可保留；战网账号验证仍为人工处理。游戏错误页连续确认并短暂等待约 3 秒即请求恢复，经原有 PID/创建时间校验关闭、等待实际退出、核对残留、通过战网启动。人工操作待机、停止和普通桌面限制保持生效，不在用户持续操作其他窗口或安全桌面时发起游戏输入。

RecoveryBudget 改为常量大小的冷却状态，没有每小时次数上限；失败间隔依次 30/60/120 秒，后续保持 120 秒。游戏启动超时持续恢复，去掉自动重试一次的终止条件。非授权类加载器失败也继续恢复；1223 取消、5 拒绝访问和 740 要求授权仍显示人工处理。次数不限不会代替用户完成授权、配置或解除进程权限限制，安全清理无法完成时仍显示具体原因。界面“自动恢复”标注次数不限；恢复计数保留为统计。

## 2026-10-09 · 0.5.9 退出与启动失败分离

本轮直接读取当前 agent.log、安装目录 log/NeacLoader.log、Neac.log 与 NeacBak.log；没有结束用户游戏或加载器、点击启动或操作授权窗口。

当前助手日志的三次掉线恢复都在约 6 秒后报告游戏缺失，再通过加载器/客户端残留检查；本轮日志没有“无法关闭已验证的游戏进程”或残留清理拒绝记录。Neac 客户端日志包含远端连接超时 10060 等记录，随后助手识别登录/连接错误进入恢复。加载器日志与进程快照匹配：PID 34000 在日志记录的 00:49:02 启动，00:51:06 明确写入 `neac start process failed 1223`。助手同一启动周期在 00:49:05～00:51:05 等待安全桌面，之后继续空等至 00:53:03。Windows 1223 是 ERROR_CANCELLED；结合安全桌面时段，可判断启动取消与授权环节有关，但不能把它表述成旧游戏终止被拒绝，也不能仅凭这些记录区分用户主动取消和授权超时。

旧版 waitingGame 分支不检查加载器的直接失败结果，只等待游戏进程和 120 秒截止时间，第一次超时又清理重试，造成已明确失败仍停在战网、重复授权。新版仅从配置安装目录读取最近 64 KiB 的加载器日志，用点击启动前的文件时间隔离旧失败，解析完整数字错误记录和对应 PID；新启动记录撤销旧错误。当前启动失败时立即显示代码并暂停，取消后不自动重试。用户自行启动游戏成功时检测到新进程并继续监控；“重启游戏”也可重新尝试正常流程。

另修复实际退出较慢时的状态处理：先用查询/等待权限尝试 WM_CLOSE，再请求终止权限；保留 PID、创建时间和普通桌面/运行代数校验。终止被拒绝时显示 PID、阶段和 Windows 错误码。终止已接受但 30 秒内未退出时保持 WAITING_GAME_EXIT，继续核验至终止后的约 120 秒；不重复终止、不清理反作弊、不启动游戏。进程晚退出会继续恢复，权限查询失败不当作已退出；待机与安全桌面暂停退出计时。仅无窗口的进程直接进入终止请求，无空耗的正常关闭等待。

6. 断网、游戏退出、登录页停滞后验证恢复边界；观察 `WAITING_FOCUS`、`NEEDS_USER` 和 `BACKOFF` 的原因。
7. 用任务管理器记录客户端与游戏各自的 CPU / 内存，再做至少一轮较长运行，以实际测量判断资源和稳定性。

不把“进程存在”当成“已进入房间”；远程 `ACTIVE` 只表示本轮游戏已匹配过用户录制的房间特征且处于房间会话，不证明当前参赛或获得经验。校准错误或特征不唯一仍可能误判。
