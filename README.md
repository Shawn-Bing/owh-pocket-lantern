0.5.8 修复死斗结算后返回街机页面重复点击入口并暂停：区分街机标题与常驻页签，保留各轮 OCR 的死斗卡片证据，补充原色局部卡片识别。

0.5.6 重构原生界面布局：支持拖动边框缩放、最大化和 DPI 自适应。顶部操作与底部状态固定，中间配置区在高度不足时滚动；软件架构、配置格式及挂机逻辑沿用现有实现。

本地端使用 C++20 / Win32；看板使用 Go 标准库、HTTP 和 SSE。日常运行使用 Windows 内置简体中文 OCR 与页面模板；界面更新时重新读取文字和实际按钮位置。0.5.0 增加可选的本地视觉模型学习：演示一次点击流程，或采集失败页面交给模型审查，再生成当前助手可导入的配置。附带原生录制和标注工具，使用时无需 Python。详见 [演示学习与本地模型指南](docs/LOCAL-VISION.zh-CN.md)。

最新真实日志与截图显示，0.4.1 已从目标浏览卡片进入 Workshop 对局，但加载约 69 秒后无法识别局内。0.5.0 修复进房候选过早失效与局内缺少房间标题的问题，并提供“已在局内，开始挂机”入口。当前房内截图正反回放通过；本机 Qwen3-VL-8B 已实测生成候选配置，通过两张房内截图及三个非房间负例；模型误选的不稳定区域会被验证拒绝。**补丁后的完整挂机循环、稳定模型校准与死斗连续重排仍需实机确认**。验证事实见 [验证记录](docs/VALIDATION.md)。

## 快速开始

如果今晚先定位“挂机途中为什么掉线”，可独立运行 `owh-recorder.exe`：记录游戏截图、相关进程、网络参考探测、网卡/连接表、原生日志和 Windows 事件，不发送按键或恢复游戏。[整夜记录步骤与数据边界](docs/RECORDER.zh-CN.md)。

下载并解压 Windows 试用包，先阅读 [Windows 试用指南](docs/QUICKSTART.zh-CN.md)。

以下为开发版步骤；日常简易版见上方双版本说明。

1. 双击 `overwatch-helper-dev.exe`，在 Windows UAC 提示中授权以管理员身份运行。默认开启演练模式，不发送键鼠、不启动或关闭游戏。
2. 保留“本地 OCR / 自动校准”，填写战网和 OWNeacClient.exe 路径，选择“自定义房间 / 战令”或“自由死斗 / 自动匹配”。自定义模式填写目标名，默认“最稳轮换版”；不同模式共用该文字时填完整标题。
3. 先演练确认页面和点击位置，再停止并取消演练，点“开始”运行。已手动进入目标房间时可点“已在局内，开始挂机”，仍需两次局内画面确认；需要重启时点“重启游戏”。继续使用原 PowerShell 点按脚本时，取消“发送挂机按键”。**F8 停止助手、取消本次录制/模型标注并释放自有按键；它不会停止外部脚本或模型服务。**
4. 如需远程看板，运行 `owh-dashboard.exe`，浏览器打开 `http://127.0.0.1:8765`。将服务端的 Agent 令牌配置到客户端，用查看令牌登录网页。

附带 `owh-demo.exe` 和 `start-demo.cmd`，可先用模拟大厅、房间和断线页面练习，不需要打开游戏。演示与正式客户端使用独立配置目录。

此前新增的“运行诊断”按钮和 `diagnose.cmd`，报告检查进程、窗口、启动器与校准，不包含令牌、机器名、服务器地址或搜索文字。F8 现在也能取消录制倒计时和校准覆盖层；停止后重新开始时，旧检测轮次不能继续发送输入。输入发送失败也计入重试上限。

## 已实现

- “演示 / 本地模型校准”：原生窗口启动 `owh-teach.exe` 记录实际点击、Enter/Esc 和对应页面，F9 仅观察、F10 明确标记目标房间。`owh-vision-calibrate.exe` 调用本机视觉模型标注、采样真实图像并验证，输出审查文件与通过的页面配置；配置导入前校验并备份旧文件，导入不会自动开始输入。
- Workshop 进房候选保留 180 秒，等待长地图加载；目标 Join 或本次明确房间标记结合连续两次局内 HUD 才建立会话。地图介绍、黑屏、普通无来源 HUD 不算进房；动态 HUD 不写入永久自适应缓存。

- 通过窗口与进程身份查找国服游戏，读取 PID / 创建时间，避免根据过期 PID 结束其他进程。
- “重启游戏”共用自动恢复流程；在关闭游戏前检查路径和启动识别配置。游戏缺失时启动配置的战网程序或快捷方式，通过 OCR、预设或校准按钮启动游戏，等待最多 120 秒。
- 内置国服“连接战网服务超时”多区域识别，连续确认并短暂等待约 3 秒后恢复；普通蓝色加载画面不会触发。也支持自定义错误模板及窗口连续 30 秒未响应恢复。
- 本地 OCR 结合页面上下文、唯一按钮文字及可用状态识别页面，适配按钮移动和游戏斜体文字。识别结果连续确认后保存到 `adaptive-profile.json`；缓存不匹配时重新 OCR，保留旧预设与手动校准。
- 自定义房间：开始 → 更多模式 → 自定游戏 → 按完整标题分组选择目标卡片 → 自动加入。相同完整标题的多个房间实例可依次尝试；不同标题仅共享子串时等待更精确目标。按当前识别的位置每 200 ms 点击一次加入，单轮最多 5 秒 / 25 次；未进房则切换下个同模式实例，5 轮无进展后等待 15 秒再试。未知或加载帧不算加入成功，需连续两次正向房间证据。
- 窗口化视频设置页使用顶部设置标签和默认设置上下文识别，按 Esc 返回导航；浏览页每次重新识别，不保存或复用 Browser 缓存；Join 缓存核对完整标题、位置、页面与按钮，支持快速连点并允许背景光效及无关人数变化。
- 自由死斗：导航、开始匹配、等待队列、选英雄、局内随机按键、结算后重新匹配；没有直接重新匹配按钮时，确认结束后离开并再排队。随机键为 W、S、A、D、V、E、Q、左 Shift，单次按住 100–500 ms；未知画面、菜单、队列与结算暂停随机输入。
- 战网重新联网弹窗遮挡游戏超过 5 秒时，尝试一次切回游戏，恢复画面检测。
- 游戏完全退出后核验配置路径、PID 与创建时间，再清理残留 `OWNeacClient.exe`。路径或权限无法核验则暂停，不结束其他安装目录的同名进程。
- 锁屏或安全桌面期间暂停输入和启动超时；每次 NeacProtect 授权仍需用户手动处理。
- 恢复次数不限，按 30/60/120 秒冷却后继续重试；超时、识别歧义、操作无进展时显示明确状态。
- 自定义房间导航：页面特征 → 两次确认 → 操作 → 再识别。支持点击、Enter、Esc、输入文字、房间就绪与恢复页面。
- 自定义模式连续确认房间参考后每秒点按左 Shift（按下 20 ms），也可选择前台持续按住。观战、结算、加载期间保留房间会话；已识别菜单、错误页、歧义、进程更换或停止清除会话。死斗使用独立的局内证据，不使用持续按住 Shift。
- 你在用电脑时助手自动待机：检测到你自己的键鼠活动（而非助手注入的）就整体停手，停止操作若干秒后自动接管。时长在界面上可设（3–600 秒，默认 10 秒）。
- 原生本地面板：配置、状态、校准列表、匹配分数、恢复次数、日志入口。
- 远程看板：30 秒常规心跳、状态变化上报、90 秒离线判定、200 条事件历史、重连与本地持久化。

## 当前边界

所有注入的按键和点击都只在目标前台进行：全局键鼠事件送达的是**当前焦点窗口**，因此游戏失焦时助手停键并等待，待机期间不截图或恢复。使用开始/F8 控制，不受 CapsLock 控制。运行时画面检测需目标前台、可见且无遮挡；最小化或遮挡时没有新画面证据。若要持续检测蓝色掉线页，请保留游戏前台；短时无采样采用现有掉线计时容忍。小窗口保持原宽高比；HDR 和滤镜仍需实测。

可继续已保存的战网登录会话，识别可用的登录、重新连接和进入游戏按钮；账号密码、验证码、过期认证与 NeacProtect / UAC 提示仍需人工处理，不自动填写或保存游戏账号密码。

OCR 需要 Windows 可用的简体中文 OCR 语言功能，`ocr-worker.ps1` 必须与助手 EXE 放在一起。文字过小、主题/语言变化、遮挡或全新结构可重新演示给本地模型，或手动校准。模型只在你请求标注时运行；它可能选错特征，配置仍需审查与回放，不能保证所有未来版本永久适配。旧截图预设只覆盖已录布局，非默认房间不使用旧目标卡片坐标。通用 HUD 本身不能独立证明目标房间或经验。

昨晚的网络中断、不活跃移出和战网遮挡证据见 [整夜记录分析](docs/OVERNIGHT-20260920.zh-CN.md)。

截图与恢复工作在后台线程，看板网络上报在独立线程。Windows 截图 API 的极端阻塞情形尚未做到独立进程隔离。不能据此保证无人值守恢复所有图形驱动故障。

主程序内嵌管理员权限清单，双击时由 Windows 请求 UAC 授权，以便向同权限游戏发送输入。没有修改防火墙、注入游戏/宿主进程或改写样本文件。本项目原生实现与 `reverse-analysis` 中的旧样本分开。

## 构建与测试

### Windows 一键构建

已安装 CMake、Go，以及 MSVC 或 MinGW-w64 时，在仓库根目录运行：

```powershell
.\scripts\build-windows.ps1
# 可选：Go 并发检测，需要 GCC
.\scripts\build-windows.ps1 -Race
# Go 不在 PATH 时
.\scripts\build-windows.ps1 -Go 'C:\path\to\go.exe'
```

脚本运行 CTest 和 Go 测试，将程序、OCR 脚本、预设、启动脚本和指南放入 `dist`。Windows 额外测试原生 OCR；简体中文 OCR 不可用时该项标记为跳过。首次构建会探测编译器；已存在构建缓存时复用其生成器。可显式传入 `-Generator 'Visual Studio 17 2022'`。打包 Windows 版本可运行 `python scripts/package.py --windows-only`。

### Windows / Visual Studio 2022

需要 CMake、Go，以及带 C++ 桌面工作负载的 MSVC。Go 的 race 测试另需兼容的 C 编译器：

```powershell
cmake -S . -B build -A x64
cmake --build build --config Release
ctest --test-dir build -C Release --output-on-failure
cd server
go test ./...
New-Item -ItemType Directory -Force ../dist
go build -trimpath -ldflags="-s -w" -o ../dist/owh-dashboard.exe .
```

### macOS / Linux 交叉构建

使用 Zig 0.15.2 与 Go 1.22+：

```sh
python3 scripts/build.py --zig /absolute/path/to/zig
cmake -S . -B build/native
cmake --build build/native
ctest --test-dir build/native --output-on-failure
cd server && go test -race ./...
```

交叉构建会输出 Windows x64 客户端、演示窗口，以及 Windows / Linux x64 / macOS arm64 看板服务端。Windows 原生端无需 Python、Zig 或 Go 运行时；OCR 使用系统 Windows PowerShell 和 Windows OCR 组件。

## 项目结构

```text
agent/             Windows 面板、校准、采集、本地 OCR、输入与恢复
core/              语义页面/缓存、图像匹配、死斗状态机与恢复预算
profiles/          识别步骤数据文件（国服 16:9 预设）
tests/             核心行为测试
server/            Go 服务端与内嵌网页
scripts/           构建脚本与 Windows OCR 工作进程
docs/              试用、架构与测试说明
reverse-analysis/  原始样本的静态分析与证据
```

配置、日志和 `adaptive-profile.json` 保存在 `%LOCALAPPDATA%\OverwatchHelper`；OCR 中间图像位于 `adaptive`，未识别截图位于 `unmatched`，演示录制位于 `teaching`，模型配置和审查位于 `calibrations`。`local-vision.ini` 保存本机模型地址与名称；导入的 `cn-profile.json` 覆盖旧预设，并保留带唯一名称的旧文件备份。模型请求只发往本机回环地址，这些图像和识别缓存不上传看板。演示模式为 `%LOCALAPPDATA%\OverwatchHelperDemo`。服务端数据位于启动目录下的 `owh-server-data`。凭据、日志、构建产物和逆向样本二进制不进入 Git。

开发测试可使用 `overwatch-helper.exe --demo --data-dir "E:\test folder\demo"` 指定隔离配置。`--diagnose` 只写入该目录的 `diagnostics.txt`，不显示面板、不发送输入、不启动游戏、不上报网络。

更多信息：[架构与协议](docs/ARCHITECTURE.md)、[验证记录](docs/VALIDATION.md)。
