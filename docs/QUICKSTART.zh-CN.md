# Windows 0.3.0 试用指南

适用：Windows 10/11 x64，国服战网版。先把 ZIP 全部解压到一个普通目录，再运行 EXE。

仓库本机构建完成后，也可以直接从 `dist` 目录运行。首次建议先点“运行诊断”确认进程、启动器和模板情况；报告保存到配置目录的 `diagnostics.txt`。也可双击 `diagnose.cmd`，它会生成并打开正式配置的诊断报告，不启动游戏或发送输入。

## 这次先测试重启游戏

1. 关闭旧助手，打开新版 `overwatch-helper.exe`，确认标题为 0.3.0。保留“国服预设”和“自动恢复”。继续使用原 PowerShell 点按脚本时，**取消“房间内发送 Shift”**，避免两边重复发送。
2. 核对启动器 `D:\Battle.net\Battle.net.exe`、OWNeac 路径 `D:\Overwatch\_retail_\OWNeacClient.exe`（这是本机已核对的路径，其他电脑按实际安装目录填写）。战网保持登录并选中守望先锋，先保留“演练”。点底部“重启游戏”，状态应显示“演练：将恢复游戏”，游戏不会退出。
3. 点“停止”，取消“演练”，再点“重启游戏”。助手会关闭游戏，等退出完成后清理核验过的残留客户端，在战网识别“进入游戏”并点击。出现 NeacProtect 授权时由你手动确认。
4. 让游戏保持前台且无遮挡。进入游戏主界面后，预设尝试“开始 → 更多模式 → 自定游戏 → 最稳轮换版 → 自动加入”。如果已经回到自定义浏览页，则直接选目标卡片再加入，不必重启。观察是否进入正确房间；遇到 `UNKNOWN` / `WAITING_FOCUS` / `NEEDS_USER`，保留页面和状态便于修正。
5. 成功后保持助手运行。以后已识别的“连接战网服务超时”连续出现 90 秒，才进入同一重启流程。F8 停止助手；外部 PowerShell 脚本仍由 CapsLock 或其窗口控制。

不用每次都点“重启游戏”：已在房间内时点“开始”即可监控。首次试用需要你在旁处理授权，当前版本不能绕过每次启动的 NeacProtect 提示。

预设来自昨晚实际截图：约 16:9 客户区、浏览页左下的“托比昂战令 最稳轮换版”。它核对文字后才点击，列表排序或缩放变化时可能不匹配。战网预设还要同时识别守望先锋标志和“进入游戏”文字；更新、正在游戏、登录页面不会仅凭蓝色按钮被当作可启动。不同布局用下方手动校准补充，或关闭预设完全使用自己的模板。

战网在网络恢复后自行弹出并遮挡游戏时，助手在 5 秒后尝试一次切回游戏；Windows 若拒绝前台切换，仍需手动切回。其他应用遮挡或最小化时无法检测游戏画面。

## 手动校准最小流程（预设不适用时）

如果你当前已经进入目标自定义房间，第一轮只需要录制一个“到达目标房间”页面：

1. 手动进入指定房间，把游戏设为窗口化；保持窗口完整可见。
2. 打开 `overwatch-helper.exe`。暂时保留“演练（不执行动作）”。
3. 校准对象选“游戏”，操作选“到达目标房间 / 持续 Shift”，页面名称填你容易辨认的名称。
4. 点击“3 秒后录制”。助手会切到游戏；三秒后截图覆盖在窗口上。
5. 拖动圈选一块**独特且静止**的房间标识/UI 特征。选取带有文字、图标或边缘的区域，避免纯色、英雄动画、计时器、聊天和会变化的数值。对局通用血条本身不能证明是目标房间。
6. 回到助手点击“开始”。游戏置于前台后，连续两次匹配应显示演练确认信息。
7. 按 F8 停止，取消演练，勾选“房间内发送 Shift”，方式选“每秒点按（20ms）”，再次开始。需要切走窗口仍点按时，保留“切到后台仍全局点按”。

状态显示 `ACTIVE` 表示本轮游戏已连续确认过房间参考，后续 HUD 短暂消失仍保留会话；不代表当前有效对局或已获得经验。**软件只能验证所选特征；是否能区分其他房间取决于校准区域。**

默认使用你提供的脚本同类 `keybd_event` 点按，每次按下左 Shift 20 ms，约每秒一次，不需要 CapsLock。后台点按属于全局输入，会影响当前前台应用；F8 停止。关闭后台选项或选择持续按住时，失焦释放 Shift。关闭助手会退出程序，不能关掉窗口后仍期待它工作。

## 手动配置完整恢复（关闭预设时）

1. 关闭旧助手，打开新版；正式配置仍使用原来的目录，导航录制保留。
2. 在已进入的目标房间，新增“到达目标房间 / 持续 Shift”，圈选 **E 技能的齿轮图标本体**，尽量避开周围场景、按键文字和数字。只录此参考不能区分其他托比昂房间，因此首次应由你确认已经进对房。
3. 演练确认后 F8，取消演练，选择每秒点按并开始。观察技能效果；切换前后台，再等到结算/下一局，确认点按继续。若初始参考无法确认，可录另一份同类 E 图标样本；无需删除其他有效导航。
4. 在“OWNeac 路径”填写实际安装目录内的 `OWNeacClient.exe` 完整路径。只有游戏已退出、进程身份核验成功时才清理该文件对应进程。权限不足或无法核验时会显示 `NEEDS_USER`，需手动处理。
5. 为蓝色掉线页录制“登录/错误页超时恢复”，圈选“抱歉，我们无法让您登录 / 连接战网服务超时”等稳定错误文字，**不要只圈纯蓝背景**。它必须持续匹配 90 秒；中断、遮挡或无截图会重新计时。不点击游戏内“登录”。
6. 把战网“进入游戏”以及“开始 → 更多模式 → 自定游戏 → 目标模式 → 自动加入”各页面录好。掉线后流程为：退出游戏 → 等待退出完成 → 清理核验过的残留 → 战网进入游戏 → 你处理 NeacProtect 授权 → 自动按录制路径重新进房。

启动助手时游戏已经缺失，会先等待 30 秒，避免把正在手动启动的客户端当成残留；助手主动结束游戏后等待 3 秒再核对残留。每次启动游戏后的 120 秒等待不包含检测到的安全桌面时间。

若需要蓝色掉线检测持续工作，请把游戏缩小放在无遮挡的位置；完全遮挡或最小化时仅能继续点按、检查进程与响应，不能识别蓝色画面。多录一份房间参考只增加小图模板采样；有效场次统计尚未实现。

## 自定义其他房间的导航

按你平时手动操作的顺序，为各个不同页面分别录制。例如：

| 当前页面 | 操作 | 第二次点击的位置 |
|---|---|---|
| 战网的守望先锋页面 | 战网启动游戏 | 启动按钮 |
| 游戏大厅 | 点击按钮 | 自定义游戏入口 |
| 自定义列表页 | 点击按钮 | 搜索入口或目标房间行 |
| 房间搜索页 | 输入文字并 Enter | 搜索输入框 |
| 搜索结果页 | 点击按钮 | 指定房间条目 |
| 房间详情页 | 点击按钮 | 加入按钮 |
| 目标房间 / 对局 | 到达目标房间 / 持续 Shift | 不需要 |
| 游戏内断线或登录页面 | 登录/错误页超时恢复 | 不需要 |

这只是流程示意，界面层级应按你的国服客户端实际页面录制。列表排序会变化时，不要把固定行号当成房间身份。优先使用搜索筛选，确保结果唯一后再标记加入位置。

“输入文字并 Enter”会点击校准的输入框、选择其中已有文字、写入设定内容，再按 Enter。不要把房间密码或账号密码当作普通搜索内容录入；配置文件以本机明文保存。

校准包含两个阶段：先拖动圈选页面特征；需要点击或输入时，再单击操作位置。**框出的特征区域与按钮位置可以不同。** Esc 取消覆盖层；F8 可取消录制倒计时或覆盖层。校准过程中不能启动任务。

多个“到达目标房间”样本、或多个“登录/错误页超时恢复”样本可以共存。同一类观察不会互相构成歧义；导航样本冲突、或房间与错误页冲突时会显示 `AMBIGUOUS` 并停止房间输入。应删除相似校准，选择更独特的页面区域，而不是降低阈值强行执行。一个页面需要多次同类操作时，应优先找出每次操作后可区分的视觉状态。

## 战网启动配置

程序尝试从常见安装位置发现 Battle.net。若路径为空或不正确，用“浏览”选择你平时启动国服战网的 EXE 或快捷方式。启动参数可以留空；不会自动添加未经验证的启动参数。

战网仅在后台托盘运行、没有可见主窗口时，助手会打开一次配置的战网程序以请求显示主窗口；仍未出现会等待并超时暂停。可手动打开战网后继续。

战网应保留有效登录状态，并显示正确的游戏页面。账号过期、验证码、客户端更新需人工处理。每次开始或恢复时，助手会尝试一次前台切换；Windows 若拒绝请求，助手会停在 `WAITING_FOCUS`，你需要切到对应窗口。开启国服预设及自动恢复后，战网持续遮挡游戏还会触发上文的一次切回尝试。

恢复规则：进程缺失可启动配置的程序；游戏窗口连续无响应 30 秒，或你校准的游戏登录/错误页持续 90 秒时尝试恢复。先请求正常关闭，最多等待 5 秒；仍未退出时，只结束身份已核对的游戏进程。每小时最多 3 次恢复，设有冷却。

启动后 120 秒没有出现游戏、页面重复操作 3 次没有前进、文本输入后页面没有变化等情形，会显示 `NEEDS_USER`。处理后点击停止，再重新开始。恢复次数上限在本次助手进程内计数，退出助手后重新运行会重置预算。

## 不开游戏也能验证

双击 `start-demo.cmd`。它会启动演示窗口和使用独立配置的助手。

先手动依次打开并校准：

1. 大厅标题区域 → 点击“进入自定义游戏”。
2. 房间列表标题区域 → 点击“加入测试房”。
3. 目标房间标题区域 → “到达目标房间 / 持续 Shift”。
4. 点击演示窗口“模拟断线”后，圈选断线标题 → “登录/错误页超时恢复”。

回到演示大厅（按 Esc），先演练再执行。正常流程是进入房间，并在前台演示窗口看到“左 Shift 点按”次数每秒增加。20 ms 脉冲很短，不需要一直显示按下。演示模式的断线持续确认时间是 5 秒，正式模式是 90 秒。F9 关闭演示窗口，可验证进程缺失后的启动与再次导航。

演示只验证软件流程，不证明国服游戏会接受所有模拟输入。

## 看板先在本机试

1. 在解压目录双击 `start-dashboard.cmd`，保持服务端窗口打开。
2. 打开浏览器访问 `http://127.0.0.1:8765`。
3. 服务端首次运行会创建 `owh-server-data`。用文本编辑器查看其中 `view-token.txt`，填到网页登录框。
4. 在 Windows 助手中填写看板地址 `http://127.0.0.1:8765`，把 `agent-token.txt` 填入“Agent 令牌”，再保存。
5. 数秒内应出现设备。停止挂机任务时仍会发送心跳；退出助手后约 90 秒看板标记离线。

两个令牌用途不同，填反会出现 HTTP 401。机器名需要在各台设备之间保持唯一。

## 部署远程看板

Windows 服务端可运行：

```powershell
.\owh-dashboard.exe -listen 0.0.0.0:8765 -data .\owh-server-data
```

Linux x64 包可运行：

```sh
chmod +x owh-dashboard-linux-amd64
./owh-dashboard-linux-amd64 -listen 127.0.0.1:8765 -data ./owh-server-data
```

公网访问应在前方配置 HTTPS 反向代理，再把 HTTPS 地址填入助手。HTTP 模式适合本机或受信任网络测试，因为令牌会随每次请求传送。反向代理需允许 SSE 长连接并关闭该路径的代理缓冲。服务端默认只监听回环地址。

本版用一个 JSON 快照持久化设备和最近 200 条事件，每 10 秒落盘；没有引入 SQLite 依赖。最多接入 128 台设备和 32 个并发查看连接，适合先行验证。

## 排障与反馈

- `BACKGROUND_INPUT`：已确认房间后继续全局点按；被遮挡/最小化时不能检测掉线画面。
- `WAITING_DESKTOP`：等待返回普通桌面；NeacProtect 授权需要手动处理，启动超时会暂停。
- `WAITING_FOCUS`：把目标窗口放到前台；不要最小化。
- `UNKNOWN`：当前页面没有模板、特征变化或窗口宽高比不同，先手动核对并重新校准。
- `AMBIGUOUS`：两份模板相似，重新选取独特特征。
- `INPUT_BLOCKED`：输入失败或目标焦点变化。助手与游戏的权限等级不同也可能造成此问题，需要结合实际提示排查。
- `BACKOFF`：恢复次数或间隔达到限制，界面会显示等待时间。
- 看板失败：确认服务端在线、地址可访问以及令牌用途正确；看板故障不会停止本地任务。

“配置与日志”会打开 `%LOCALAPPDATA%\OverwatchHelper`。日志 `agent.log` 超过约 512 KiB 后轮转一份。反馈时提供状态、相关日志以及实际页面截图；分享 `settings.ini` 前请移除 `token` 字段。

当前测试与实测边界见验证记录；真实国服输入、校准和恢复仍需实测。完整验证范围见 `VALIDATION.md`。
