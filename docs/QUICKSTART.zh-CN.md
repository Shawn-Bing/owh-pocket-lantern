# Windows 第一版试用指南

适用：Windows 10/11 x64，国服战网版。先把 ZIP 全部解压到一个普通目录，再运行 EXE。

## 先试最小流程

如果你当前已经进入目标自定义房间，第一轮只需要录制一个“到达目标房间”页面：

1. 手动进入指定房间，把游戏设为窗口化；保持窗口完整可见。
2. 打开 `overwatch-helper.exe`。暂时保留“演练（不执行动作）”。
3. 校准对象选“游戏”，操作选“到达目标房间 / 保持 Shift”，页面名称填你容易辨认的名称。
4. 点击“3 秒后录制”。助手会切到游戏；三秒后截图覆盖在窗口上。
5. 拖动圈选一块**独特且静止**的房间标识/UI 特征。选取带有文字、图标或边缘的区域，避免纯色、英雄动画、计时器、聊天和会变化的数值。对局通用血条本身不能证明是目标房间。
6. 回到助手点击“开始”。游戏置于前台后，连续两次匹配应显示演练确认信息。
7. 按 F8 停止，取消演练，保留“目标房间保持 Shift”，再次开始。

状态显示 `ACTIVE` 表示匹配到你校准的房间就绪页面。**软件只能验证所选特征；是否能区分其他房间取决于校准区域。**

切换到浏览器或其他窗口会释放 Shift，并显示 `WAITING_FOCUS`；切回游戏后重新识别并继续。关闭助手会退出程序，不能关掉窗口后仍期待它工作。

## 配置掉线后重新进房

按你平时手动操作的顺序，为各个不同页面分别录制。例如：

| 当前页面 | 操作 | 第二次点击的位置 |
|---|---|---|
| 战网的守望先锋页面 | 战网启动游戏 | 启动按钮 |
| 游戏大厅 | 点击按钮 | 自定义游戏入口 |
| 自定义列表页 | 点击按钮 | 搜索入口或目标房间行 |
| 房间搜索页 | 输入文字并 Enter | 搜索输入框 |
| 搜索结果页 | 点击按钮 | 指定房间条目 |
| 房间详情页 | 点击按钮 | 加入按钮 |
| 目标房间 / 对局 | 到达目标房间 / 保持 Shift | 不需要 |
| 游戏内断线或登录页面 | 登录/错误页超时恢复 | 不需要 |

这只是流程示意，界面层级应按你的国服客户端实际页面录制。列表排序会变化时，不要把固定行号当成房间身份。优先使用搜索筛选，确保结果唯一后再标记加入位置。

“输入文字并 Enter”会点击校准的输入框、选择其中已有文字、写入设定内容，再按 Enter。不要把房间密码或账号密码当作普通搜索内容录入；配置文件以本机明文保存。

校准包含两个阶段：先拖动圈选页面特征；需要点击或输入时，再单击操作位置。**框出的特征区域与按钮位置可以不同。** Esc 取消本次校准。

同时匹配多个页面时会显示 `AMBIGUOUS` 并暂停操作。应删除相似校准，选择更独特的页面区域，而不是降低阈值强行执行。一个页面需要多次同类操作时，应优先找出每次操作后可区分的视觉状态。

## 战网启动配置

程序尝试从常见安装位置发现 Battle.net。若路径为空或不正确，用“浏览”选择你平时启动国服战网的 EXE 或快捷方式。启动参数可以留空；不会自动添加未经验证的启动参数。

战网应保留有效登录状态，并显示正确的游戏页面。账号过期、验证码、客户端更新需人工处理。每次开始或恢复时，助手会尝试一次前台切换；Windows 若拒绝请求，助手会停在 `WAITING_FOCUS`，你需要切到对应窗口。日常手动切走游戏不会触发反复抢焦点。

恢复规则：进程缺失可启动配置的程序；游戏窗口连续无响应 30 秒，或你校准的游戏登录/错误页持续 90 秒时尝试恢复。先请求正常关闭，最多等待 5 秒；仍未退出时，只结束身份已核对的游戏进程。每小时最多 3 次恢复，设有冷却。

启动后 120 秒没有出现游戏、页面重复操作 3 次没有前进、文本输入后页面没有变化等情形，会显示 `NEEDS_USER`。处理后点击停止，再重新开始。恢复次数上限在本次助手进程内计数，退出助手后重新运行会重置预算。

## 不开游戏也能验证

双击 `start-demo.cmd`。它会启动演示窗口和使用独立配置的助手。

先手动依次打开并校准：

1. 大厅标题区域 → 点击“进入自定义游戏”。
2. 房间列表标题区域 → 点击“加入测试房”。
3. 目标房间标题区域 → “到达目标房间 / 保持 Shift”。
4. 点击演示窗口“模拟断线”后，圈选断线标题 → “登录/错误页超时恢复”。

回到演示大厅（按 Esc），先演练再执行。正常流程是进入房间，并在演示窗口看到 Shift 状态变化。演示模式的断线持续确认时间是 5 秒，正式模式是 90 秒。F9 关闭演示窗口，可验证进程缺失后的启动与再次导航。

演示只验证软件流程，不证明国服游戏会接受所有模拟输入。

## 看板先在本机试

1. 在解压目录双击 `start-dashboard.cmd`，保持服务端窗口打开。
2. 打开浏览器访问 `http://127.0.0.1:8765`。
3. 服务端首次运行会创建 `owh-server-data`。用文本编辑器查看其中 `view-token.txt`，填到网页登录框。
4. 在 Windows 助手中填写看板地址 `http://127.0.0.1:8765`，把 `agent-token.txt` 填入“Agent 令牌”，再保存。
5. 数秒内应出现设备。停止挂机任务时仍会发送心跳；退出助手后约 90 秒看板标记离线。

两个令牌用途不同，填反会出现 HTTP 401。机器名需要在各台设备之间保持唯一。

## 部署远程看板

Windows 服务端可运行：

```powershell
.\owh-dashboard.exe -listen 0.0.0.0:8765 -data .\owh-server-data
```

Linux x64 包可运行：

```sh
chmod +x owh-dashboard-linux-amd64
./owh-dashboard-linux-amd64 -listen 127.0.0.1:8765 -data ./owh-server-data
```

公网访问应在前方配置 HTTPS 反向代理，再把 HTTPS 地址填入助手。HTTP 模式适合本机或受信任网络测试，因为令牌会随每次请求传送。反向代理需允许 SSE 长连接并关闭该路径的代理缓冲。服务端默认只监听回环地址。

本版用一个 JSON 快照持久化设备和最近 200 条事件，每 10 秒落盘；没有引入 SQLite 依赖。最多接入 128 台设备和 32 个并发查看连接，适合先行验证。

## 排障与反馈

- `WAITING_FOCUS`：把目标窗口放到前台；不要最小化。
- `UNKNOWN`：当前页面没有模板、特征变化或窗口宽高比不同，先手动核对并重新校准。
- `AMBIGUOUS`：两份模板相似，重新选取独特特征。
- `INPUT_BLOCKED`：输入失败或目标焦点变化。助手与游戏的权限等级不同也可能造成此问题，需要结合实际提示排查。
- `BACKOFF`：恢复次数或间隔达到限制，界面会显示等待时间。
- 看板失败：确认服务端在线、地址可访问以及令牌用途正确；看板故障不会停止本地任务。

“配置与日志”会打开 `%LOCALAPPDATA%\OverwatchHelper`。日志 `agent.log` 超过约 512 KiB 后轮转一份。反馈时提供状态、相关日志以及实际页面截图；分享 `settings.ini` 前请移除 `token` 字段。

客户端尚未在 Windows 国服游戏上动态验收，CPU 和内存没有实测数值。试用包经过交叉编译、核心逻辑测试和看板协议测试，详细范围见 `VALIDATION.md`。
