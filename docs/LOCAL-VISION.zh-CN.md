# 演示学习与本地视觉模型（0.5.0）

0.5.0 支持把你的操作演示变成页面识别配置：录制器记录每次实际点击前的画面和坐标，本地视觉模型标注页面与稳定特征，程序从真实截图生成模板并验证。导入后由助手按“识别页面 → 连续确认 → 执行动作 → 再识别”运行。游戏更新时可以只重新录制失效页面，再审查与导入新配置。学习窗口会读取已导入的配置作为基础，保留其它页面；改变房间目标时清理旧目标的房间规则。

## 现在已在房间，先恢复运行

主窗口选“自定义房间 / 战令”，确认当前游戏确实在目标房间，点击 **“已在局内，开始挂机”**。这个入口把目标声明绑定到本次游戏进程，仍要连续两帧看到局内 HUD；不会把任意游戏 HUD 永久记录成该房间。演练模式、发送挂机按键和用户输入待机设置继续生效。

自动从浏览页加入时，目标加入候选现保留 180 秒，覆盖较长地图加载；地图介绍和黑屏等待，出现可信局内画面后确认。停止、进程变化或手动离开到导航页面会撤销身份。

## 连接已运行的视觉模型

本机已发现 `http://127.0.0.1:8080` 上的 llama.cpp / Qwen3-VL-8B 视觉服务，可以直接使用；无需重新安装或重启该服务。学习窗口的“模型名称”留空会通过模型列表自动选择唯一模型；同一接口有多个模型时填写实际模型 ID。它必须支持图片输入，纯文本模型不能完成页面标注。

其他电脑可以连接自己的本机 OpenAI 兼容视觉接口。本功能只接受 `127.0.0.1`、`localhost`、`[::1]`，支持根地址或 `/v1` 等工具支持的 API 路径；本地地址通过 HTTP/HTTPS 与模型交换图像。llama.cpp 的服务与多模态接口说明见 [官方服务器文档](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md) 和 [官方多模态文档](https://github.com/ggml-org/llama.cpp/blob/master/docs/multimodal.md)。模型文件和对应视觉投影组件应与该服务版本相容。

随包的录制和标注程序是原生 EXE，用户不需要 Python。模型进程本身由你原来的启动方式管理；助手仅连接接口，F8 不会关闭模型服务。

## 演示一次操作流程

1. 按 F8 停止助手，点主窗口 **“演示 / 本地模型校准”**。学习窗口打开时自动运行和手动覆盖层校准互斥。
2. 点击 **“录制操作/页面”**，在弹出的录制窗口点击开始。回到战网或游戏，按你平时的步骤点击。每次等画面稳定后再操作；过快连点可能因缺少对应新画面而被跳过。
3. 录制器记录目标窗口中的左键点击、Enter、Esc，与这些动作发生前的客户区截图。切换到其他应用时暂停采集；普通文字键不会记录成键盘宏。
4. 到达目标房间后按 **F10** 明确标记。继续停留约 **1–2 秒**，让录制器保存第二帧验证画面；不要立即切走或完成。F10 标记提供房间身份，单独一张普通血条不能代替该声明。
5. 按 **F8**，或在录制窗口完成并关闭。学习窗口自动载入本次 `manifest.json`。
6. 点击 **“开始模型标注”**。下方显示日志；完成后点 **“查看结果”**打开图文审查页，检查原截图上的橙色锚点框、绿色实际点击圈和验证结果是否符合演示。没有审查页时打开输出目录。
7. 验证完成后点 **“导入配置”**，或主窗口 **“导入页面配置”** 选择已生成的 `profile.json`。原配置先备份，再原子替换；房间目标随配置同步。
8. 关闭学习窗口，回到主窗口先演练。确认页面和拟执行动作后停止、取消演练并开始实际运行。导入动作自身不会启动挂机。

截图会包含目标应用当时显示的内容；账号登录、验证码和 UAC 仍由你处理。只录需要自动化的页面即可。

## 更新后自检或修复一个页面

页面改版后，打开录制器，在需要检查的页面按 **F9**。F9 保存“观察”步骤，供模型提出页面分类和区域建议，**不会直接生成带动作的执行规则**。若该页面需要自动点击，请另外实操一次对应按钮；若它就是目标房间，请用 F10 标记并等第二帧保存。

模型猜测的点击位置不会覆盖你实际演示的位置。生成的房间规则还需跨验证帧匹配；缺第二帧或匹配失败只保留审查信息，应重新录制稳定画面或调整标注。本轮实际 Qwen3-VL 曾把天空选作锚点并被拒绝。工具随后把可选区域限定为从真实图像筛选的稳定候选，最终房间配置通过两帧验证；区域的文字标签仍可能不准确，应以审查页上的实际框和点击点为准。

## 结果与文件

默认数据目录为 `%LOCALAPPDATA%\OverwatchHelper`。

| 文件/目录 | 内容 |
|---|---|
| `local-vision.ini` | 模型地址、模型名、最近录制与配置位置 |
| `teaching/<唯一会话>/manifest.json` | 动作、实际点击位置及对应截图引用 |
| `teaching/<唯一会话>/` | 录制 PNG 和房间第二帧 |
| `teaching/<唯一会话>.log` | 录制器运行日志 |
| `calibrations/<唯一任务>/profile.json` | 通过校验的页面配置；失败时可能不存在 |
| `calibrations/<唯一任务>/profile.json.review.html` | 可视化审查：原图、锚点、点击位置和验证状态；离线打开 |
| `calibrations/<唯一任务>/profile.json.review.json` | 模型建议、采纳或拒绝原因 |
| `calibrations/<唯一任务>/run.log` | 标注进程日志 |
| `cn-profile.json` | 已导入并用于识别的配置 |
| `cn-profile-backup-*.json` | 导入前的唯一备份，失败时也保留原配置 |

“标注与源图回放验证完成”表示工具成功生成配置；“没有通过的可执行步骤”表示仅有审查或验证失败，不能据此声称已经修好。模型标注成功也不等于实机完成整个登录、进房和挂机循环。

F8 / 取消结束本次任务。录制器先保存 manifest 再退出；标注器被取消后保留已有日志。关闭学习窗口时先取消并等待自己的子进程完成，用户原有模型服务继续运行。

## 可选命令行

图形窗口已经覆盖正常流程。需要复用录制或排障时，也可以直接运行随包工具：

```powershell
.\owh-vision-calibrate.exe --session "C:\my-recording\manifest.json" --endpoint "http://127.0.0.1:8080" --out "C:\my-calibration\profile.json"
```

模型名可加 `--model "实际模型ID"`；已有配置可加 `--base-profile "C:\my-calibration\existing.json"` 保留其它校准。输出需使用另一个文件路径，不能覆盖输入配置。退出码 `0` 表示生成、回读及回放通过；`3` 表示审查已生成但没有可接受动作或验证失败；`1` 表示输入格式或文件操作失败，`2` 表示缺少必要命令行参数。先打开 `profile.json.review.html` 查看图文结果；详细字段在 `profile.json.review.json`，异常在日志中，再决定需要补录哪个页面。
